# 安全设计

本文是本项目安全设计的**单一真源**：威胁模型、防御映射、配对握手、端点契约、措施清单。评审与实现均以本文为准。

## 0. 一页速览

- **首要威胁是「网页攻击本地」**——用户浏览器里的任意网页都能访问 `127.0.0.1`。历史上大量本地服务默认「能连到环回地址的就是可信的」而不做鉴权，因此被随便一个恶意页面拿下。
- **四个攻击方向各有正交防御，缺一不可**（§1）。
- **三道主防御**：`bind 127.0.0.1` + `Origin 白名单` + `运行时随机配对码`。
- **配对码由本进程运行时用 CSPRNG 生成**，绝不来自构建期、绝不进公开产物、绝不进 URL。
- **握手用 HMAC 挑战-响应**：配对码明文永不上线。这也是凭证可持久化的前提。
- **凭证以数据传递**：工具只返回配对码字符串，绝不返回需要执行的脚本。

## 1. 威胁模型：四个方向

判断任何措施前，先把它归位到某个方向。

| 方向 | 攻击者 | 能否伪造 `Origin` | 主防御 |
| --- | --- | --- | --- |
| **① 网页 → 本地** | 用户浏览器里打开的恶意网页 | ❌ 不能（浏览器强制带真实 Origin，JS 改不了） | **S1 bind + S2 Origin 白名单** |
| **② 本地进程 → 本进程** | 机器上的恶意进程（curl / native app） | ✅ 能（不走浏览器，Origin 随便填） | **S3 运行时配对码**（Origin 对它无效） |
| **③ 本地冒充者 → 页面** | 抢先占用固定端口、冒充本进程 | — | **S10 挑战-响应 + S4 端口占用检测** |
| **④ 分发/提示投毒 → 页面** | 冒充本进程的 MCP server、被污染的分发包、文档内容里的 prompt injection | — | **S13 数据而非代码 + S5 默认只读 + S6 裁决权** |

### 1.1 为什么方向①是首要威胁

`evil.com` 的 JS 可以直接 `new WebSocket('ws://127.0.0.1:19837')`。若本进程不校验 Origin、不校验凭证，evil.com 就能读走并改动用户所有打开的文档。**注意读工具本身就是数据外泄路径**——不能因为写操作有建议态兜底就放松读侧防护。

### 1.2 防御与方向的对应（务必记牢）

- **Origin 白名单 = 挡方向①**：Origin 是浏览器替网页盖的「我是谁」的章，网页伪造不了，所以本地服务能靠它甄别来源。
- **运行时配对码 = 挡方向②**：本地进程能伪造 Origin，只能靠它不知道的运行时秘密来挡。
- **挑战-响应 = 挡方向③**：固定端口下冒充者可抢占端口钓凭证，挑战-响应让凭证不上线。
- **数据而非代码 = 挡方向④**：凭证以数据流转，杜绝任意代码执行通道。

> 四者正交，各挡一类，一个都不能省。

## 2. 凭证模型

### 2.1 反面教材：构建期生成的"校验码"（禁用）

构建期生成 = 编译期常量 = **公开产物里的明文**。前端包可下载、可 grep，**印在公开包里的值不是秘密**。且全体用户同一个码，无 per-session 隔离，一次泄露全网通杀。后果是 S3 直接失效，只剩 Origin 一道防线，而它挡不住方向②。

若"校验码"本意是前后端版本对齐，那作为**版本 pin** 合理，但必须明确它不是安全控制。

### 2.2 正解：运行时生成（标准设备配对码模型）

| 属性 | 要求 |
| --- | --- |
| 生成方 | **本进程运行时**（非构建期、非配置文件长期固化） |
| 随机性 | CSPRNG，熵 ≥ 128 bit（本实现 256 bit hex） |
| 生命周期 | per-session；进程重启即换；`revoke_session` 可主动轮换 |
| 交付 | 经 MCP 通道以**数据**返回，或用户从终端复制 |
| 页面侧存储 | `sessionStorage`；**禁止进 URL**（会漏进 referer / history / 服务端日志） |
| 上线方式 | **不明文提交**，走挑战-响应（§3） |

## 3. 发现与配对

### 3.1 页面如何发现本进程

页面看不到进程列表、读不了本地文件，唯一手段是往 localhost 已知地址发探测。这正是**固定端口的正当用途**：发现必须有已知地址。按需探测（用户打开面板时）或加载时探一次 + 退避，不做激进轮询。

### 3.2 三态与 UI 暴露原则

发现结果分三态，但**只在确实需要用户输入凭证时才展现 UI**（避免常驻提示干扰编辑）：

| 状态 | 判据 | 页面表现 |
| --- | --- | --- |
| 未运行 | 探测超时/连不上 | **无 UI** |
| 运行但未配对（无已存凭证） | `/health` 可达且无会话 | 弹出配对输入框（唯一展现 UI 的时机） |
| 运行且有已存凭证 | sessionStorage 有配对码 | **无 UI**，静默自动重连 |
| 已连接 | 握手成功 | **无 UI**；撤销经 `hook.disconnect()` 或桥侧 `revoke_session` |

> **残留权衢**：取消常驻指示器后，用户在页面上看不到「当前有 Agent 已连接」，也没有可点的撤销入口（S11 的用户可见部分弱化）。
> 当前实现面向开发/内部环境，可接受；**若未来开放给真实用户，必须在已有菜单/设置里提供连接状态与撤销入口**（不必是浮层）。

### 3.3 挑战-响应握手

```
1. 用户启动本进程 → CSPRNG 生成 per-session 配对码
2. 页面探测到 → 浮出输入框
3. 配对码进入页面（MCP 工具返回的数据经 UI 填入，或用户粘贴）
4. WS 握手（配对码不上线）:
     页面 → 本进程: OPEN(ws://127.0.0.1:<port>)      # 校验 Origin 白名单
     本进程 → 页面: { type:'challenge', nonce }
     页面 → 本进程: { type:'auth', mac }             # mac = HMAC-SHA256(配对码, nonce)
     校验 mac: 通过 → { type:'ready', sessionId }；失败 → { type:'error', code:'AUTH_FAILED' } + close 4003
5. 成功 → 页面把配对码存 sessionStorage，供刷新后自动重连
```

**为什么不明文提交配对码**：固定端口下恶意本地进程可抢先 bind 端口冒充本进程；若页面明文发凭证即被截获，攻击者可拿真凭证连真进程。挑战-响应下，冒充者无凭证无法伪造 mac，且监听到 mac 也反推不出凭证（HMAC 单向）。

## 4. 端点契约

### 4.1 `GET /health`（握手前可访问，按 Origin 分级）

| 请求来源 | ACAO | 响应体 |
| --- | --- | --- |
| 白名单内 | 回**具体源** + `Vary: Origin` | `{ ok, service, version, originAllowed, port, connected, pageReady, allowWrite }` |
| 白名单外 | 回具体源 | 仅 `{ ok, service, version, originAllowed:false }` |

**关键**：白名单外**不得**读到 `connected` / `allowWrite` 等状态——它们是可用于踩点与定向攻击的指纹。ACAO 一律不用 `*`。

同时应答 `Access-Control-Allow-Private-Network: true`，以便浏览器收紧本地网络访问策略后仍可放行。

### 4.2 `WS /`

- 仅 bind `127.0.0.1`（S1）
- **upgrade 阶段**校验 `Origin`，不通过直接 403（S2）
- 建连后走挑战-响应，未通过前不接受任何工具调用

### 4.3 结构化错误码

| code | 含义 |
| --- | --- |
| `PORT_UNREACHABLE` | 端口未开（本进程未运行） |
| `PORT_CONTENDED` | 候选端口全被占用（疑似抢占） |
| `ORIGIN_REJECTED` | Origin 不在白名单 |
| `AUTH_FAILED` | 挑战-响应校验失败（配对码错/已轮换） |
| `HANDSHAKE_TIMEOUT` | 建连后未在时限内完成握手 |
| `PNA_BLOCKED` | 浏览器拒绝本地网络访问 |
| `BAD_MESSAGE` / `PROTOCOL_MISMATCH` | 消息格式或协议版本不符 |

## 5. 措施清单（实现验收项）

| # | 措施 | 挡的方向 |
| --- | --- | --- |
| **S1** | 仅 bind `127.0.0.1`（不做成可配置） | ① |
| **S2** | Origin 白名单，upgrade 阶段 403；默认**逐条枚举官方环境**，**不用宽泛通配**（如 `*.example.com`）；自建域需 `--allow-origin` | ① |
| **S3** | 运行时 CSPRNG 配对码，per-session | ② |
| **S4** | 端口占用检测：候选集顺延，全占用明确报错 | ③ |
| **S5** | 默认只读，写工具需显式 `--allow-write` | 全 + ④ |
| **S6** | 破坏性/落盘类操作需用户明确许可（约束下沉到工具描述与页面侧） | 全 + ④ |
| **S7** | 连接失败结构化诊断（§4.3） | 全 |
| **S8** | 单连接会话制：新会话顶掉旧会话 | 全 |
| **S9** | 审计日志：记录工具名、时间、来源 Origin；**不记录配对码与参数值** | 全 |
| **S10** | HMAC 挑战-响应，凭证不上线 | ③ |
| **S11** | 凭证生命周期：`sessionStorage` 分区隔离；提供撤销（轮换 + 断连） | ②④ |
| **S12** | PNA 响应头就绪 | 全 |
| **S13** | **凭证以数据传递，绝不返回可执行代码** | ④ |

## 6. 残余风险

- **同源 XSS**：能读 `sessionStorage` 的同源 XSS 可拿凭证连桥；但同源 XSS 本已能直接驱动页面编辑器，**风险不新增**。撤销机制可缩小窗口。
- **高权限本地进程**：已以用户权限运行的恶意进程本可直接为害；本设计确保它**至少无法静默经本桥读写文档**（被 S3/S10 挡）。
- **本地网络访问策略收紧**：浏览器对 `localhost` 访问在逐步收紧为需授权。S12 预置响应头 + S7 诊断降低"升级即碎"，需持续跟踪内核策略。
- **固定端口冲突**：靠候选集 + S4 检测 + `PORT_CONTENDED` 诊断处理。
- **方向④残余**：即便凭证以数据传递，若 Agent 被 prompt injection 诱导调用写工具，仍受 S5（默认只读）+ S6（裁决权）+ 建议态三重兜底——最坏情况是「用户看到一批可拒绝的建议」，而非静默篡改。
