# 设计说明

## 1. 问题

AI Agent 想编辑「用户浏览器里已经打开的那篇钉钉文档」，面临三个约束：

1. 文档的编辑能力（块级读写、建议态修改）只存在于**页面运行时**，服务端 API 无等价语义
2. Agent 通常跑在**浏览器之外**（IDE、终端、桌面客户端）
3. 直接让 Agent 注入并执行脚本，等于把任意代码执行权交给一条不可信链路

本项目解决的是第 2、3 条：在不注入任何脚本的前提下，把页面运行时的工具暴露给浏览器外的 MCP host。

## 2. 链路

```
任意 MCP host（IDE / 终端 / 桌面 Agent）
   ↕ stdio（标准 MCP，JSON-RPC over newline-delimited JSON）
alidocs-web-mcp（本进程：配对 + 哑管道转发）
   ↕ ws://127.0.0.1:<port>（页面主动出站连接）
文档页面内的 MCP Server → 页面工具 → 建议态修改
```

**方向反转是可行性关键**：不是本进程去连浏览器（那需要浏览器暴露调试端口，且被大多数宿主禁止），而是**页面主动出站**连本地进程。页面 JS 本来就有网络能力，无需任何宿主特权。

## 3. 三个不可拆分的耦合

设计中有三对决策互为前提，实现时不能单独改动其中一半：

### 3.1 零脚本注入 ⟺ 可发现端口

要做到「Agent 不执行任何返回的代码」，页面必须**自己发现**本地进程；页面唯一的发现手段是往本机已知地址发探测请求。因此端口必须是**固定候选集**（本项目：19837/19838/19839），而不能是随机端口——随机端口的信息只能靠注入脚本携带，那就回到了注入。

### 3.2 凭证持久化 ⟺ 挑战-响应

页面刷新会销毁 JS 上下文。若每次刷新都要重新配对，体验不可接受；于是配对码需要存在 `sessionStorage` 里以便自动重连。但这把凭证从「一次性」变成「长期存在」：如果握手是明文提交凭证，那么每次重连都把凭证再交给「当时占着那个端口的进程」一次。

因此**必须**用 HMAC 挑战-响应：本地进程下发随机 nonce，页面回 `HMAC(配对码, nonce)`，配对码明文永不上线。冒充者即使截获 mac 也无法反推配对码。

### 3.3 配对码是数据 ⟺ 无需注入

配对码经 MCP 工具以**字符串数据**返回，由 UI 自动化（填入输入框）或用户粘贴进入页面。填数据是有界能力；执行返回的代码不是。只要坚持「工具只返回数据，绝不返回需要 eval 的脚本」，注入类风险即被移除。

> 反面教材：让本地进程返回一段「引导脚本」再由 Agent 执行。这等于把 RCE 做成了产品特性——任何能冒充本地进程或污染其分发的人，都能在用户已登录的会话里执行任意代码，且与文档内容里的 prompt injection 叠加放大。**本项目明确禁止该模式。**

## 4. 为什么本进程是哑管道

除三个自有工具（`get_pairing_code` / `get_bridge_status` / `revoke_session`）外，本进程**不理解任何文档业务语义**：

- `tools/list`：把自有工具与页面上报的工具合并返回，不改写 schema
- `tools/call`：按名字路由——自有工具本地执行，其余原样转发给页面，结果原样回传
- 页面工具的参数校验、语义、错误由页面侧负责

这样做的收益：页面侧新增/修改工具**不需要动本进程**；同一个桥可服务任意实现了本协议的页面。

## 5. 会话与生命周期

- **单连接会话制**：同时只服务一个页面连接；新连接握手成功会顶掉旧连接（旧连接收到关闭码 4008）。这让「工具属于哪篇文档」语义恒定为「当前配对的那个页面」。
- **页面刷新即断桥**：断连时在途请求立即收到结构化错误（`PAGE_DISCONNECTED`），不挂起等超时；页面用 `sessionStorage` 里的配对码自动重连。
- **撤销**：`revoke_session` 轮换配对码并断开会话，页面侧存储的旧码随即失效。

## 6. 错误处理原则

任何失败都必须回**结构化错误码**而不是让调用方空等：

| 场景 | 表达方式 |
| --- | --- |
| 页面未连接 / 已断开 | 工具结果 `isError` + `PAGE_NOT_CONNECTED` / JSON-RPC 错误 + `PAGE_DISCONNECTED` |
| 页面响应超时 | `PAGE_TIMEOUT`，并向页面下发取消通知 |
| 握手/连接类失败 | 见 [security.md](./security.md) §4.3 错误码表 |

页面侧同样据 `/health` 探针把「端口未开 / Origin 被拒 / 升级失败 / 本地网络被拦」区分开，避免只能报「连不上」。

## 7. 模块边界

```
src/protocol/   协议单一真源（零依赖）：版本、服务标识、控制消息、错误码、HMAC、一致性向量
src/            实现层：配置、密钥、会话、WS server、帧编解码、JSON-RPC 路由、stdio、审计
```

依赖**单向向上**：实现层可依赖 protocol，反之不可。页面侧有一份等价的 TS 镜像实现，两侧都断言与 `src/protocol/vectors.json` 逐字一致——这是防止两端协议漂移的唯一可靠手段（各自 mock 会形成"契约幻觉"）。

## 8. 已知取舍

- **固定端口**带来端口冲突可能：用候选集 + 启动时占用检测（全部被占则明确报错 `PORT_CONTENDED`）化解，而不是静默失败。
- **`sessionStorage` 作用域**：刷新与同标签同源导航保留，新标签/浏览器重启不保留。取舍理由：新标签重新配对成本低，而 `localStorage` 会显著放大凭证暴露窗口。
- **页面侧能力是前提**：本进程只是桥，文档工具由页面提供。页面若未加载对应的连接器实现，`discover` 会一直是 `not-running`。
